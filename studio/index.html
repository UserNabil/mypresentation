 Packaging — client assets archive (.pkg): unpack to edit, then pack back in

  

    
Reading archive…


    
    

      
 Working set
        Which archive the three operations read from or write to, and which folder holds the loose files. The folder does not need to contain pkg.idx — a brand-new empty folder is a perfectly valid destination. Leave both on their defaults to work on the configured client, as before.

      

        
        
        
      

      

        
        
        
      

      

    


    

      
 Depack incremental
        Decompress the client .pkg into the unpacked client root, so you can edit the files. Only files that actually changed in the archive — or that you edited on disk — are re-extracted; everything already up to date is skipped. Leave the folder box empty for the whole archive, or type a subtree (e.g. data\db, several separated by ;) to depack just that.

      

        
        
        

      

    


    

      
 Repack surgical
        Re-inject the files you changed AND add new files you dropped in, back into the .pkg of the working set. Preview first: per-folder summary, the reason for every file left out, warnings for files the game may not show. Exactly the checked files are written — only those, never re-compressing the rest — with automatic .bak backups; each one is then read back the way the game reads the pkg and the whole folder is checked.

      

        
        

      

    


    

      
 Verify pkg game view
        Is every game file of the folder in the archive, identical (size and content), where the game looks for it? The index is read exactly the way game_.exe reads it. Lists what is missing, different or unreadable with the reason, what is not a game file and why, and copies that are older than the archive — then Fix re-injects the faulty files in one click. Read-only.

      

        
        

      

    


    

      
 Diff & Mods Vault rebase-safe
        Full comparison of the unpacked tree against the packed archive — + added, ~ modified, − removed — with a per-file preview (images render, other files show their type). Before you rebase / re-copy a clean client, save your modified files into the Vault; restore them afterwards so nothing is lost.

      

        
        
        

      

    


    

      
 Pack full
        One click, no preview: writes every changed and new file of the folder into the archive (only those — nothing else is re-compressed), reads each one back the way the game does, then checks the whole folder.

      

        

      

    

  

  







  
 Client Deploy env
    — publish the client to the launcher CDN · scoped to the ACTIVE environment

  

    
Everything here targets the … environment only. Generate version.json from a staging client folder (pkg or full-unpacked), preview exactly what changed, upload only the changed files to this env's CDN bucket, and roll a version back. Files are never deleted from the CDN, so rollback is always possible.


    

      
 Configuration per-env
        Where the client lives and where it's published for this env.

      

        
        
        
        
        
        
        
      

      

        

      

    


    

      
 R2 credentials optional
        How to reach the bucket — stored in .secrets.json, never shown back. Leave a field blank to keep its current value.

      

        
        
        
        
      

      

        

      

    


    

      
 Preview & select
        Scan the staging client, build version.json, and see exactly what a deploy would upload.

      

        
        
        
        

      

    


    

      
 Publish to CDN
        Upload the changed files + version.json to the env bucket. Only what changed is sent.

      

        

      

    


    

      
 History & rollback
        Every published version is kept — re-publish a previous one to revert every client.

      

        

      

    


    

      
 Launcher files
        Publish the launcher's config / news file, or launcher.exe itself, to this env+channel CDN.
